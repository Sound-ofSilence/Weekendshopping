# P12 优化与安全

## 已确定的决策（不要再问）
- 一期只做 4 项：接口限流 + 敏感信息脱敏 + 越权校验 + 越权测试
- 其余（防重放、文件上传、等保）延后到 P13 上线前
- 限流用 @nestjs/throttler（官方推荐）

## 功能 1：接口限流

安装依赖：pnpm add @nestjs/throttler（手动，不要在代码里改 package.json）

限流规则：
- 全局默认：60 次/分钟（每 IP）
- 登录接口 /auth/login：5 次/分钟（每 IP + 手机号组合）
- 发短信 /auth/send-sms：1 次/60秒 + 10 次/小时
- 下单 POST /orders：10 次/分钟
- 秒杀 POST /seckill/products/:id/buy：5 次/分钟

实现：
- 在 app.module.ts 里注册 ThrottlerModule.forRoot
- 用 @Throttle() 装饰器覆盖默认限流

## 功能 2：敏感信息脱敏

规则：
- 手机号：138****8888（前3后4，中间4位星号）
- 身份证：110101********1234（前6后4）
- 银行卡：**** **** **** 1234（只显示后4位）
- 邮箱：a***@example.com

应用位置：
- /admin/users 列表里手机号脱敏（已做）
- /seller/orders 列表里收货人手机号（receiverJson.phone）
- 其他暴露手机号的接口

## 功能 3：越权校验

用 3 类校验：
- 横向：用户 A 不能查用户 B 的资源（订单、地址、售后）
- 纵向：普通用户不能调管理接口（用 @Roles 守卫）
- 状态：未完成订单不能评价，已取消订单不能发货

需要 review 现有接口，补齐漏掉的校验。

## 功能 4：越权测试

至少 3 个测试用例：
- 用户 A 查用户 B 的订单 → 404 或 403
- 普通用户调 /admin/* → 403
- 商家查其他商家的订单 → 404

## 输出要求
- 先输出文件清单，用户确认后编码
- 严禁跑命令
- 只输出 diff
